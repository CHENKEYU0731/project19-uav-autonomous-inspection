# M4 Mission State Machine Implementation Plan

> **Historical record:** This implementation plan is retained for design history only.
> M4 is accepted; current status and evidence are authoritative in
> [`docs/m4-mission-audit.md`](../../m4-mission-audit.md). Current work is limited
> to the M5 gates.

## Scope

Implement only M4 from the authoritative project scheme. Preserve the accepted M2 map/TF contract and the accepted M3 planner/controller safety behavior by making all M4 controller behavior opt-in.

## ROS Contracts

- `/drone_planner/goal` (`geometry_msgs/PoseStamped`): active inspection or home goal.
- `/drone_planner/status` (`drone_interfaces/PlannerStatus`): goal result; statuses older than the goal publication are ignored.
- `/drone_mission/command` (`drone_interfaces/MissionCommand`): explicit LAND command to the controller.
- `/drone_mission/event` (`drone_interfaces/MissionEvent`): structured, ordered FSM/event log recorded in rosbag.
- PX4 local position/status/land detection: takeoff and final landing observations.

## FSM

`STANDBY -> TAKEOFF -> INSPECTING -> HANDLING_EXCEPTION -> RETURNING_HOME -> LANDING -> COMPLETE`

Normal waypoint progress may remain in `INSPECTING`; every progress event is still published. A persistently unreachable waypoint passes through `HANDLING_EXCEPTION`, logs the skipped index and reason, then publishes the next waypoint. Simulated low battery passes through `HANDLING_EXCEPTION`, discards the remaining inspection plan, then retraces successfully reached inspection waypoints in reverse order before publishing home. This breadcrumb return avoids requiring a new direct route through conservatively unknown space and does not relax the M2/M3 map or trajectory safety gates.

## Direct Acceptance Evidence

1. Unit tests prove every FSM branch and invalid-event rejection.
2. Source/launch tests prove M4 is opt-in and all evidence topics are recorded.
3. A real SITL rosbag proves ordered mission events, at least two inspection goals, an unreachable skip, a low-battery return, a changed trajectory around the dynamic obstacle, home arrival, LAND command, landed/disarmed state, and zero collision messages.
4. Gazebo and RViz2 are captured together; the final video duration is checked to be no more than 180 seconds.

Items 1-4 have direct evidence in `log/m4/inspection_video_20260823_220601/`,
`docs/assets/m4-inspection-demo.mp4`, and `docs/m4-mission-audit.md`. M4 is
accepted; subsequent work proceeds under the M5 gates.

## Failure Policy

- Stale/mismatched planner state never advances the FSM.
- Transient `NO_PATH` does not skip a waypoint.
- Planner/map loss remains subject to the M3 controller hold-and-land safety timeout.
- Mission or required-process nonzero exit propagates to the top-level launch.
- Runtime evidence is rejected if the launch exit code, bag, mission event sequence, collision evidence, landing state, or video duration is missing.
